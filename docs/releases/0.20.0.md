# SCV Claude Code 0.20.0

Released: 2026-07-28

## Shared core

- Common workflow, shell helpers, templates, DeckUI, assets, protocols, and
  tests now come from the independent
  [`scv-core`](https://github.com/wookiya1364/scv-core) release.
- `vendor/scv-core/` and root `core.lock` pin the core version, API, template
  version, source commit, canonical payload SHA-256, materialized payload
  SHA-256, and release tarball SHA-256. A local checkout records a `null`
  artifact digest.
- Installed commands never fetch core at runtime.
- Existing `${CLAUDE_PLUGIN_ROOT}/scripts`, `template/`, `DeckUI/`, and
  `assets/` paths remain generated compatibility projections.

## Shared project state

- New projects use only the host-neutral `scv/SCV.md` workflow index, producing
  the same hydrated tree under Claude Code and Codex.
- Existing `scv/CLAUDE.md` and `scv/CODEX.md` state remains readable without
  mutation. Explicit sync backs up and pointerizes only legacy files that
  already exist, and stops on conflicting state.

## Claude adapter

- `/scv:*`, command `allowed-tools`, per-command `model:`,
  `AskUserQuestion`, plugin update/reload, and model-policy behavior stay
  adapter-owned.
- Raw `$ARGUMENTS` remains prompt data only and is forbidden in pre-model
  ```` ```! ```` shell blocks. Parsed spaces, quotes, and shell metacharacters
  are passed to helpers as inert arguments.
- `scripts/sync-core.sh` supports a local core checkout and immutable public
  releases.
- Core sync advances root `VERSION`, the Claude plugin manifest, and the
  marketplace catalog version together; hydrated-state schema remains
  independently pinned in `TEMPLATE_VERSION`.
- `scripts/verify-core.sh`, wrapper contract CI, and the scheduled/manual
  or release-dispatched `chore/core-v*` → `develop` PR workflow verify every
  pin before promotion.
