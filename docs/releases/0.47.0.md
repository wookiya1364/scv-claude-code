# 0.47.0

두 가지가 바뀝니다. 비운 뒤에도 이어지고, 명령이 skills 구조로 옮겨집니다. Core pin 은 `0.47.0`.

## 대화를 지우거나 압축·재개한 뒤에도 하던 일을 압니다

지금까지는 `/clear` 를 치거나 컨텍스트가 자동 압축되거나 세션을 재개하면, 다음 턴의
모델이 방금까지 하던 계획·결정·대화를 몰랐습니다. 저장은 이미 자동이었는데 다시 읽어
주는 훅이 없었습니다.

- `SessionStart` 이벤트(`compact|clear|resume` 에만)에 코어의 되찾기 템플릿을 등록했습니다.
  진행 중 계획, 최근 결정 5건, 미결 사항, 그리고 가장 최근 활성 대화 1건 전문(가림 필터
  경유)이 첫 턴에 실립니다. 새 세션 시작(startup)에는 뜨지 않습니다 — 첫 메시지의
  preflight 가 이미 상태를 싣습니다.
- 훅은 아무 것도 쓰지 않고 항상 exit 0 입니다. 끄려면 설정 파일에 `SCV_RESUME_RECAP=off`.
- 상한은 두지 않았습니다(결정·대화가 길 수 있다는 판단). 실측: recap 약 1.5KB.

## 명령이 `skills/<action>/SKILL.md` 로 옮겨집니다

Claude Code 문서가 `commands/` 를 legacy 로 표시합니다. 열다섯 명령을 같은 이름의
`skills/<action>/SKILL.md` 로 옮기고 `commands/` 는 없앴습니다. **호출 이름 `/scv:<action>`
은 하나도 바뀌지 않습니다.** 갱신 뒤 스킬이 두 번 보이면 `/reload-plugins` 한 번.

- 투영·갱신 소유 규칙·모델 정책·계약 검사·워크플로가 새 경로를 봅니다.
- PR 게이트: `claude plugin validate --strict` 를 마켓 매니페스트 · 플러그인 매니페스트 ·
  `skills` · `agents` 넷에 각각 돌립니다(루트 하나만 돌리면 마켓 매니페스트만 봅니다).
- 코어 검사 `test-skill-descriptions.sh` 가 벤더링되어 CI 에서 돕니다: `name` 이 디렉터리명과
  같고, 설명이 개별 1,536자 · 합계 8,000자(지금 5,709자) 이내이며, `model:`·`context:` 줄이
  없어야 합니다.
