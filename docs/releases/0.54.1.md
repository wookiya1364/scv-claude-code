# 0.54.1

규칙이 부딪히면 누가 이기는지를 한 곳에 적습니다. Core pin 은 `0.54.1`.

## 무엇이 달라지나

- **규칙 헌법.** `scv/SCV.md` 의 Top-level rules 절이 최상위 층이 됩니다. 조항 7개 — 묻고 추측하지 않는다 · 보관은
  불변 · 영수증 없는 쓰기 금지 · 같은 요구는 한 곳에만 · 검증 없는 완료 선언 금지 · 순수함수 파이프라인 · 사용자
  지침에 양보 — 는 각각 이미 있던 규칙을 요약하고 출처를 가리킵니다. 그 아래 해소 순서 한 문단: 조항 > 더 좁은
  범위의 규칙 > 실행 중 액션의 단계 규칙(상시 문구보다) > 대체를 선언한 나중 규칙. 선언 없이 어긋나는 두 규칙은
  버그입니다 — 어느 쪽을 따랐는지 한 줄로 밝히고 기록합니다. 이 문단이 해소 순서를 적는 유일한 자리이고, 우선순위를
  말하던 세 곳은 참조로 바뀌었습니다.
- **회귀 삭감이 결정 표 하나로 묻습니다.** 실패한 슬러그마다 질문 하나씩 던지던 것이 슬러그별 행을 둔 표 한 장으로
  바뀝니다. 행마다 regression / obsolete / flaky 와 추천이 있고, 한 번에 답합니다. `--ci` 는 그대로 묻지 않습니다.
- **재발을 막는 검사.** 우선순위 어휘를 담은 문장이 헌법 절 밖에 있으면 참조형이거나 이유가 적힌 허용목록에 있어야
  합니다(게이트). 같은 요구가 두 문서 이상에 적힌 후보는 기준선보다 늘면 실패합니다(래칫).
- **회귀 실행기가 설정 파일 값을 자식 검사에 흘리지 않습니다.** 프로젝트에 `SCV_LANG` 같은 설정이 있으면 "설정 없음"
  을 전제한 보관 계약 검사가 실행기 안에서만 붉어지던 문제입니다. 사용자가 직접 export 한 값은 그대로 흐릅니다.
- **폐기 표시가 바로 효력을 냅니다.** 보관 색인이 보관 때만 다시 만들어져 삭감의 obsolete 표시가 다음 보관까지 무시
  되던 것을 고쳤습니다. 색인 생성은 `scripts/archive-index.sh` 한 곳입니다.
- 맥에서만 죽던 검사 둘(GNU 전용 `sed -i`, 맥 awk 가 모르는 `\x` 16진 BOM)을 고쳤습니다. 리눅스와 맥이 같은 바이트를
  봅니다.

`scv/SCV.md` 는 템플릿 지문으로 다음 Core 액션에서 자동 갱신됩니다(merge-on-markers — 프로젝트 로컬 블록은 그대로).
템플릿 스키마 번호는 오르지 않았습니다.

## 0.54.0 은 왜 건너뛰었나

0.54.0 이 더한 규칙 헌법 검사는 래퍼에 벤더링된 사본에서도 돈다. 래퍼가 명령 표기를 자기 접두어로 바꿔 배송하고 코덱스는
인자 안내 문장을 모든 프로토콜에 끼워 넣기 때문에, 사본에서 허용목록 한 줄이 어긋나고 중복 요구 기준선을 넘어 코덱스의
코어 핀 PR 이 만들어지지 않았다. 0.54.1 이 비교 전 표기를 정규형으로 맞추고 중복 래칫을 원본 저장소에서만 돌게 했다 —
그래서 두 래퍼 모두 0.54.0 을 건너뛰고 0.54.1 을 받는다.
