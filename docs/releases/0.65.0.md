# 0.65.0

다시 쓴 요청이 턴의 처음만이 아니라 일 내내 실제 일과 맞게 됩니다. Core pin 은 `0.65.0`.

## 무엇이 달라지나

- **선택 창 답 뒤 다시 등록**: 선택 창으로 답한 뒤 첫 파일 편집 전에 요청을 다시 등록해야 편집이 됩니다 — 답으로 방향이 바뀌었는데
  예전 요청으로 계속 일하던 빈틈을 막습니다. 범위가 그대로면 한 줄(`register --keep`)로 끝납니다. 이 래퍼가 선택 창 답 신호 훅을
  새로 겁니다.
- **'변경 없음' 범위는 편집을 막음**: 등록의 범위 칸을 '변경 없음 — …' 으로 시작한 턴에는 프로젝트 파일 편집이 거절되고, 범위가
  바뀌었으면 다시 등록하라고 알려 줍니다. SCV 기록 폴더는 그대로 쓸 수 있습니다.
- **세션마다 따로**: 한 저장소에서 여러 세션 · 팀원 에이전트를 써도 서로의 등록 · 막기 · 경고가 섞이지 않습니다. 팀원 에이전트는
  막히지 않고, 그 답이 작업 기록(저널)에 들어가지 않으며, 팀원이 보낸 메시지마다 리드가 다시 등록하지 않아도 됩니다.
- **가이드는 필요할 때만 다시 읽음**: 재접속 · 이어받기만으로는 모델별 가이드 원문을 다시 읽지 않습니다 — 그 세션 대화 기록에서
  마지막 압축 뒤에 읽은 흔적이 없거나 모델이 바뀌었을 때만.
- **답의 모양**: 답 맨 위에 '이렇게 이해하고 일함: …' 한 줄, 결론 바로 뒤에 다시 쓴 요청 전문.
- 64KB 를 넘는 긴 답의 끝 질문 · 가운데 문제 표도 판정합니다.
