# 0.106.0

Core 0.106.0 을 싣습니다.

**두 일을 동시에 할 수 있습니다.** 진행 중인 계획이 있는데 목표가 다른 일이 오면, 전에는 하던 일을 멈추는 길뿐이었습니다. 이제 두 일이 같은 파일을 고치지 않으면 하던 일을 멈추지 않고 가릅니다 — 하던 일은 분기(옆에 만드는 git worktree 폴더)에서 뒤에서 도는 에이전트가 이어 가고, 새 일은 원본에서 합니다. 가를 때 하던 일의 확인 명령을 돌려 결과를 적어 두고, 두 일이 끝나 합친 뒤 다시 돌려 비교합니다. `이름: 값` 꼴의 줄이 달라졌으면(예: 10 → 5) 다시 하기 단계가 계획에 붙습니다.

**겹치면 가르지 않습니다.** 두 일이 같은 파일을 고치거나 새 일이 고칠 파일을 알 수 없으면 지금처럼 멈추고 돌아옵니다. 합칠 때 두 쪽이 같은 줄을 고쳤으면 아무것도 바꾸지 않고 멈춰 알립니다.

**SCV 창(scv-dashboard 0.8.0)이 두 일을 나란히 보입니다.** 가른 단계 밑에 두 일이 '분기' · '원본' 이름표로 놓이고, 합친 뒤에는 달라진 결과와 다시 할 일이 보입니다. 같은 판에서 창은 움직임으로 상태를 알리고(일하는 중인 단계의 점이 번지고 내 차례에는 멈춤), 열린 질문을 맨 위의 카드로 띄워 단추로 답하게 합니다.

**긴 계획에서 기록이 빨라졌습니다.** 계획 글을 다시 쓰는 일(멈춤 · 재개 · 단계 넣기 · 가름 · 합침)이 글이 길어지면 줄 수의 제곱으로 느려지던 것을 고쳤습니다. 결과는 그대로입니다.

## 알아 둘 것

- 업데이트는 `/scv:update` 한 번입니다(모드도 함께 올라갑니다). 새 판은 새 세션부터 쓰입니다(열려 있는 터미널 세션은 `/reload-plugins`).
- 가르기는 원본의 작업 파일 · 색인 · 가지를 건드리지 않고, 합치기는 커밋을 만들지 않습니다(달라진 파일만 작업 파일에 옮깁니다). 분기의 폴더와 가지는 스스로 지우지 않습니다 — 지울지는 묻습니다.
- 결과 비교는 확인 명령이 `이름: 값` 줄을 찍을 때만 값의 변화를 잡습니다. 통과 · 실패만 찍는 계획은 통과 여부만 비교하고, 가를 때 그렇게 알립니다.
- 지금의 멈추고 돌아오기는 그대로입니다. 깃 저장소가 아니거나 깃이 2.38 보다 낮으면 가르지 않습니다.
- 확인은 시험(본체의 계획 연결 시험 · 대시보드 시험 328개)과 실제 창에서 본 화면으로 했습니다. 실제 긴 일에서 뒤에서 도는 에이전트가 단계를 끝까지 해내는지는 아직 보지 못했습니다.
