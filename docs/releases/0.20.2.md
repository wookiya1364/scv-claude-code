# SCV Claude Code 0.20.2

Released: 2026-07-29

## Independent wrapper release

- The Claude adapter remains version `0.20.2` while its pinned SCV Core is
  `0.20.6`, making the independent release streams explicit.
- Root `VERSION`, `.claude-plugin/plugin.json`, and the marketplace `scv`
  entry remain one wrapper-release unit.
- Core sync no longer rewrites wrapper release metadata. It updates the
  vendored Core, `core.lock`, generated compatibility paths, and Core-owned
  `TEMPLATE_VERSION`.

## Shared state-index resolver

- Claude now delegates state inspection and legacy pointer finalization
  directly to Core's host-neutral resolver without duplicating its rules.
- Claude and Codex recognize pointers by the same exact
  `<!-- SCV:HOST-POINTER target=SCV.md -->` marker, regardless of header prose.
- Divergent readable state fails closed with rc 4 and no mutation while still
  reporting an existing `INTAKE.md` project as hydrated. A pointer without
  canonical `SCV.md` remains broken and unhydrated.

## Atomic Core sync

- Release provenance is fail-closed across the requested tag, payload
  `VERSION`, repository, source commit, artifact checksum, and canonical plus
  materialized manifest/payload digests.
- A repository-local owner lock prevents concurrent sync. Dead-owner locks
  are quarantined before reclamation; malformed or symlink locks are rejected.
- Candidate, backup, and live targets share one filesystem. EXIT, error, and
  catchable signal paths restore exact prior presence, content, type, and mode.
- A failed restore keeps the recovery transaction and prints its path.
  Unfinished transactions block later sync until a maintainer recovers them.
- Ignored and untracked DeckUI runtime paths, including nested dependencies
  and generated decks, survive successful installs and rollbacks. A collision
  with a new Core-owned path stops before live mutation.
- Before the live swap, Core's migration tool additively copies known legacy
  DeckUI runtime entries into the external cache namespace keyed by the
  canonical source-payload digest. If a different host has already populated
  that namespace with conflicting data, the cache remains authoritative and
  the entire persistent legacy source is skipped to prevent partial mixing.
  The old DeckUI remains untouched in either case.
- Dirty Core-owned or local-only files under other replacement paths stop the
  sync rather than being overwritten. Adapter-owned allowlisted files remain
  untouched.
- Core-owned files are compared directly with their stage-0 index blobs using
  Git clean filters, closing stat-cache and racy-clean overwrite gaps. Git
  repository/index override environments are rejected.
- The projection writer is restricted to an authorized transaction stage and
  uses sibling temporary files plus rename. Direct live-repository writes and
  symlinks anywhere below the stage destination are rejected.
- Deck cache bases overlapping the wrapper, transaction, download temporary
  directory, or legacy DeckUI migration source are rejected before migration.
- Transaction, rollback, cross-filesystem, signal, provenance, and lock tests
  remain covered by the bounded full contract lane.

## Faster CI promotion

- Pull requests run fast contract/state/shared-regression smoke on Ubuntu and
  macOS.
- The full Ubuntu atomicity suite runs only on entry PRs targeting `develop`
  and only when updater, projection, atomic-swap, or atomicity-test files
  changed. Promotion PRs run smoke only.
- `develop` and `stage` pushes no longer duplicate checks that already passed
  on their promotion PR.
- A single full macOS contract remains on `main` as the release gate.
- Core-update automation performs smoke before opening a PR and leaves heavy
  conditional validation to that PR instead of executing it twice.
- Stale PR runs are cancelled by concurrency, and the model-policy matrix no
  longer repeats after a successful main merge.
