# scv-claude-code 0.33.0

Core 0.33.0 을 싣는다. 이번 배포는 core 0.32.0 과 0.33.0 을 한 번에 담는다.

## 설정이 `scv/scv_settings.json` 으로 — `.env` 는 더 이상 읽지 않는다

프로젝트 루트 `.env` 는 앱이 원래 쓰던 파일이라 SCV 값과 섞여 오해가 잦았다.
설정이 두 파일로 갈린다.

| 파일 | 담는 것 | 커밋 |
|---|---|---|
| `scv/scv_settings.json` | 언어·알림 제공자·PR 플랫폼·첨부/GIF 옵션 (23개) | 예 |
| `scv/scv_settings.secret.json` | 봇 토큰·저장소 토큰·채널 ID (13개) | **아니오** |

**기존 프로젝트에서 할 일**: 플러그인을 올린 뒤 첫 명령에서 "설정이 옮겨지지
않았고 지금 기본값으로 돌고 있다" 는 안내를 한 번 받는다. 한 번만 돌리면 된다.

```bash
bash "$CLAUDE_PLUGIN_ROOT/vendor/scv-core/core/scripts/settings-migrate.sh"
```

`.env` 를 **지우지 않고** SCV 가 아는 키만 옮긴다. 앱이 쓰던 값은 건드리지 않는다.

**업데이트가 설정을 덮어쓰지 않는다.** SCV 가 새 설정을 내려보내도 없는 키만
더해진다 — 정한 값도, 일부러 비운 값도, SCV 가 모르는 키도 그대로다.

토큰을 넣을 때는 스크립트를 쓰면 된다. 비밀 키는 무시되는 파일로 **자동으로**
가므로 실수로 커밋할 경로가 없다.

```bash
bash "$CLAUDE_PLUGIN_ROOT/vendor/scv-core/core/scripts/settings-set.sh" SLACK_BOT_TOKEN=xoxb-...
```

## 템플릿 갱신이 번호가 아니라 내용으로도 판단한다

SCV 버전은 올렸는데 워크플로 문서가 그대로 남는 일이 잦았다 — 자동 갱신이 번호로만
판단해서, 템플릿을 바꾸고 버전을 안 올리면 어느 프로젝트에도 도달하지 않았다.

이제 템플릿 내용의 지문도 본다. **번호를 안 올려도 전달된다.** 되돌림 방지와 기존
번호 경로는 그대로다.

갱신이 안 됐을 때 조용히 넘어가지 않는다. 자동 갱신을 꺼뒀거나 배포본이 불완전하면
말해 주고, `/scv:status` 에 `[template]` 절이 — **어긋났을 때만** — 나온다.

## 결정이 스스로 색인되고, 비운 뒤 한 줄로 되찾는다

결정 로그(`scv/DECISIONS.md`)는 세 지점에서 자동으로 쌓인다 — 계획 승인, 보관,
폐기 판정. 이제 그때 **위치도 함께** 남으므로, 로그 전체를 안 읽고 결정 하나만
이름으로 꺼낼 수 있다.

```bash
bash "$CLAUDE_PLUGIN_ROOT/vendor/scv-core/core/scripts/record-read.sh" --key <이름>
bash "$CLAUDE_PLUGIN_ROOT/vendor/scv-core/core/scripts/recap.sh"
```

`recap.sh` 는 컨텍스트를 비운 직후 되찾는 자리다 — 진행 중 계획, 최근 결정, 막힌
것, 미결 사항. **아무것도 새로 쓰지 않는다.** 저장은 이미 자동으로 되고 있다.

`scv/SCV.md` 에 네 곳(대화·계획·결정·저널)의 경계가 적혔다.

## 순수부와 효과부 계약

`core/contracts/purity.md` 가 세 층을 정의하고 `check-purity.sh` 가 강제한다.
새 기능은 순수함수와 파이프의 조합으로 만들고, 파일·시각·네트워크는 바깥의 얇은
층이 맡는다. 계획 작성 규칙(`scv/PROMOTE.md`)에도 들어갔다.

회귀를 돌리면 남의 기능 영상이 올라갔다. 기본이 이번 슬러그의 것만으로 바뀐다.
