# scv-claude-code 0.25.0

Pins SCV Core 0.25.1 and registers the workspace guard.

## What changes for you

The plugin now **denies** two things instead of merely advising against them:

- Creating `PLAN.md` / `TESTS.md` / `FEATURE_ARCHITECTURE.md` by hand under
  `scv/promote/`. Run `/scv:promote` — it scaffolds those files, consumes the raw
  material, and records where the plan came from.
- Editing code outside `scv/` when no SCV command has run in the session.
  `*.md`, `.gitignore`, `.gitattributes` and `LICENSE` are exempt.

Editing a plan that already exists is always allowed — filling in `<TODO>` spots
and moving `status:` are normal steps.

Any SCV command clears the block for the session, including read-only
`/scv:status`. If you drive the session with another tool (BMAD/GSD or similar),
run one SCV command first and the rest proceeds normally.

The guard is inert in projects that have not run `/scv:help` setup, and it fails
open: if anything goes wrong inside it, your action proceeds and a line goes to
stderr.

**Hooks are not hot-reloaded.** Restart Claude Code or run `/reload-plugins`
after updating, or the guard stays inactive.

To turn it off: `SCV_GUARD=off` in the environment. To keep only the plan rule:
`SCV_GUARD_RULE_B=off`.

## Also

- Pull requests that change code must now carry the plan they came from. The
  `branch-flow` check reads the plans the PR added under `scv/archive/`. Release
  and Core-sync PRs are exempt; so are docs-only PRs. For a genuine exception,
  put `[no-plan: <reason>]` in the title — an empty bracket is not accepted.
- `/scv:set-models` no longer hand-edits `.env`; it routes through a Core script
  that preserves every unrelated line.
- `tests/test-routines.sh` was failing in this repository on every run, because
  it carried Core-relative paths. No CI job ran it, so nobody saw.

## Honest limits

The guard enforces "an SCV command ran in this session", not "this edit belongs
to planned work". The CI gate is what checks the second thing, at merge time. And
a turn where the model writes no files at all is outside both — no hook event
fires when nothing is written.
