# SCV Claude Code 0.24.0

Core `0.24.0` 을 pin 한다.

## 어댑터 변경

### 승격이 버튼 하나가 됐다

`promote.yml` 이 `develop → stage → main` 을 각각 PR 로 열고, 체크를 기다리고,
병합한 뒤 `VERSION` 을 읽어 태그와 릴리스를 만든다. 영구 브랜치에 직접 push 하지
않는다 — 룰셋이 셋 다 PR 을 요구하므로 워크플로가 PR 을 열어 병합한다.

트리거는 `workflow_dispatch` 하나뿐이고, 그 수동 시작이 사람 게이트다. 체크가
빨간불이면 그 자리에서 멈추고 PR 은 열린 채 남는다.

```bash
gh workflow run promote.yml                   # 승격 + 릴리스
gh workflow run promote.yml -f release=false  # 승격만
```

### 버전이 한 곳에서 올라간다

`scripts/set-wrapper-version.sh` 를 추가했다. 버전이 다섯 곳(`VERSION`,
`plugin.json`, `marketplace.json`, README 3종의 릴리스 문구)에 있었고 릴리스마다
손으로 고쳤다. 일부만 고치면 매니페스트와 VERSION 이 어긋난 플러그인이 나간다.

## Core 0.24.0 이 가져오는 것

- CI 를 3분 30초에서 30초대로 줄였다. 원인은 죽은 PID 를 만들려고 `sleep 30` 을
  띄우고 죽이는 코드(신호가 안 닿으면 30초를 그냥 기다림)와, 경쟁 창을 만들려고
  파일 4000개를 복사하던 테스트였다.
- `scv/journal` 이 기본 gitignore 다. 훅이 자유대화까지 전부 받아쓰므로, 올릴지는
  저장소 공개 범위를 보고 사용자가 정한다.
