# 0.92.0

Core 0.92.0 을 싣습니다(0.89.2 · 0.90.0 · 0.91.0 · 0.91.1 · 0.91.2 의 변경 포함).

**재는 명령(새 기능).** 순수함수 하나(또는 셸에서 띄우는 명령 하나)의 시간 · 메모리 · GPU · 다른 프로그램을 부른 횟수와, 입력을 4배로 늘렸을 때 시간이 몇 배가 되는지를 잽니다. 순수함수 사전이 있는 프로젝트에서 사전에 오른 함수를 고치면, 턴이 끝날 때 고치기 전 코드와 견줍니다(최대 35초). 시간 1.2배 · 메모리 1.2배와 1MB · 부른 횟수 1번 · 입력 4배에 8배를 넘으면 멈추고 실제 숫자로 묻습니다. 사전이 없는 프로젝트에서는 아무것도 재지 않고, 설정 `SCV_PURE_BENCH=off` 로 끕니다.

**엮음 고르기 명령(새 기능).** 줄을 흘려보내는 단계 목록과 예시 입력을 주면, 단계마다 한 번씩만 재서 더 빠른 순서를 계산합니다(순서를 전부 돌려 보지 않습니다). 고른 순서를 한 번 돌려 답이 같은지 확인하고 표로 보여 줍니다. 코드는 바꾸지 않습니다 — 고를지는 직접 정합니다. 실측(40만 줄 · 단계 셋): 실행 5번으로 0.25초 → 0.12초, 답 같음.

**합성 설계 체크리스트.** 계획서에 "순수함수를 어떻게 엮는가"를 묻는 표가 생겼습니다. 답과 근거를 적고, 일을 끝낼 때 코드에서 다시 답합니다. 표가 없거나 근거 칸이 비면 발표 자료가 경고합니다.

**느린 함수 17개를 고쳤습니다.** 입력이 커지면 크게 느려지던 함수들입니다. 답은 그대로입니다. 맥 기본 bash(3.2)에서 매 턴 도는 언어 검사가 긴 답에서 2.6초 걸리던 것이 0.01초가 됐고, 계획 충돌 검사는 22초 → 0.12초가 됐습니다.

**고친 것.**
- 계획을 보관한 턴이 "진행 중 계획이 없다"로 막히던 것 — 그 턴에 보관한 계획의 기록도 읽습니다.
- 저널 폴더를 다른 저장소로 연결해 둔 프로젝트에서 저널이 쌓이지 않던 것.
- 권장 effort 요청이 모델이 묻지 않아도 "물었다"로 끝나던 것 — 실제로 물은 턴만 그렇게 적습니다.
