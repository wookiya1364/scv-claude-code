# 0.49.0

help 규약을 세션당 한 번만 읽습니다. 매 턴에는 기록 계약만 실리고, 진단은 바뀐 턴에만 전체가 실립니다. Core pin 은 `0.49.0`.

## 규약은 세션당 한 번, 매 턴은 기록 계약만

0.48 에서 help 본문을 13KB 로 줄였지만 여전히 매 턴 다시 실렸습니다. 20턴 세션이면 사본 20개가
컨텍스트에 쌓여 압축을 앞당깁니다. 규약을 둘로 나눕니다.

- **매 턴(SKILL.md ≈ 9.8KB)**: 인자 규칙 · 기록 없이 돌려보내지 않는다 · 언어 · 쉬운 말 · 조사 위임 포인터 ·
  **답 모양 절 전체** · 스크립트 실행 · 매 턴 계약(짧은 턴 이어붙이기, append 형식, 한 턴 한 모양). 답 모양을
  매 턴 남긴 것은 의도입니다 — "대화가 길어지면 잊는다"는 우려에 대한 답으로, 답의 계약은 사본을 아끼지 않습니다.
- **세션당 한 번(`protocols/help/full.md` ≈ 6.4KB)**: 세 모드 · 의도 분류 · 대화 루프 · 분기 포인터.
- **다시 읽을 때는 모델이 아니라 훅이 정합니다.** 표식 `scv/journal/.help-state`(ignore 대상). 매 턴 훅이
  세션 번호가 바뀌면, 그리고 `SCV_HELP_RELOAD_EVERY`(기본 10)턴마다 다시 읽게 하고, 되찾기 훅(압축·지우기·재개)도
  다시 읽게 합니다. 보조 스크립트가 `PROTOCOL: load|loaded` 를 찍고, 모델은 `load` 일 때만 규약 전체를 읽습니다.
- **진단은 바뀐 턴에만 전체.** 직전 턴과 같으면 한 줄("진단 변동 없음 — 마지막 전체 HH:MM")만 실립니다.
- 스위치 `SCV_HELP_LOAD_ONCE`(기본 on). off 면 0.48 동작(매 턴 전체, 진단 매 턴 전체)입니다.
- 계약 변경 하나: 되찾기 훅이 "아무 것도 쓰지 않는다"에서 "표식 한 파일만 쓴다(scv/journal/ 안)"로. 이 래퍼의
  `hooks.json` 설명 문구는 다음 정리 때 맞춥니다 — 동작은 이미 그렇습니다.

실측(코어): 진단 변동 없는 턴의 스택 17.7KB → 11.2KB(−36%). 세션 누적은 규약 전체를 10턴에 한 번만 더합니다.
설치 뒤 `claude plugin details scv@scv-claude-code` 로 help on-invoke 값을 재 보세요 — 0.48.1 에서 약 5.2k 였고,
이번엔 매 턴 실리는 본문이 SKILL.md 만이라 그보다 낮아야 합니다.

## 다음(계획만)

규약을 읽은 컨텍스트에만 있는 무작위 지문을 매 턴 기록에 적게 하고, 종료 훅이 지문 부재와 답 모양 위반을
감지해 다음 턴에 다시 싣는 "지문 메아리" — 통신의 체크섬·재전송과 같은 구조입니다.
